## 🔄 迭代機制

### 自動檢測規則
1. **重複討論檢測**: 系統會自動識別重複的討論主題
2. **決策變更檢測**: 當決策發生變更時，會自動標記並記錄原因
3. **進展對比**: 每次會話都會與前次進展進行對比
4. **技術債務追蹤**: 自動追蹤未解決的技術債務

### 會話模板
```markdown
### 會話 #[SESSION_ID]
**時間**: [TIMESTAMP]
**主題**: [MAIN_TOPIC]

#### 討論內容
[SUMMARY_OF_DISCUSSION]

#### 重要決策
[KEY_DECISIONS_WITH_REASONS]

#### 進展更新
[PROGRESS_UPDATES]

#### 下一步行動
[NEXT_ACTIONS]

#### 技術債務
[TECHNICAL_DEBT_ITEMS]
```

## 📝 會話記錄規則

### 自動記錄觸發條件
1. **新決策**: 任何技術或商業決策
2. **進展更新**: 完成的功能或里程碑
3. **問題發現**: 技術債務或風險識別
4. **方向調整**: 策略或計劃變更

### 會話ID生成規則
- 格式: YYYY-MM-DD-HHMM
- 例如: 2025-01-21-1430
- 自動遞增，確保唯一性

### 內容分類標準
- **決策**: 影響後續開發的重要選擇
- **進展**: 具體完成的工作項目
- **問題**: 需要解決的技術債務
- **計劃**: 下一步的行動項目
