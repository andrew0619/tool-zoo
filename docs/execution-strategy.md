## 🛠️ 技術實務指南

### 你這樣做就穩

#### 重點策略
- **重點只有一個小產品片段**：先做「門票系統」這一盒（付費→權限生效），其他先不做
- **全用現成服務，不自己造輪子**：
  - 登入/資料庫/RLS：Supabase（內建權限政策）
  - 付款：Stripe Checkout + Billing（內建訂閱與客戶入口）
  - 托管：Vercel（自動 HTTPS、環境變數）
  - 觀測：Sentry（錯誤）、PostHog（事件）
  - AI（若需要）：只放在「後端」用金鑰；輸出用 JSON/Schema 檢查（Zod）

#### AI協作策略
- 讓AI幫你「寫樣板＋改檔」，你負責「把需求說清楚」與「看結果」
- AI出錯機率>0，所以要有保險：
  - **低碼規則**：不在前端放任何金鑰；所有「改權限」都走後端，且要驗證 Stripe 簽章
  - **安全預設**：Supabase 開 RLS；Storage 預設私有；API 有速率限制
  - **指標先行**：每次請 AI 改完，都看三件事：能登入嗎？能付費嗎？付費後1分鐘內權限有生效嗎？

#### 人類審核預留
**5–10 小時找資深工程師做三件事**：
- 檢查 Stripe webhook 驗證與冪等（避免重覆扣款/授權）
- 檢查 Supabase RLS/Policies（避免越權）
- 看一眼伺服器日誌與錯誤處理（避免把機密打到前端）

這筆錢像上保險，最值。

## 📊 市場驗證方法

### 如何排除「AI 幻覺」（簡單驗證法）

#### 權限×訂閱
- 去看 Stripe Billing + Webhook + 角色/權限（RLS/Policies）官方文檔是否能組起來
- 用測試金流跑一次「付費→Webhook→資料庫權限變更」
- 量測 p95 生效時間

#### JSON-AI 可靠層
- 選一段模型容易出錯的任務（請它回合法 JSON）
- 比較「裸跑」vs「校驗+自動修復+重問一次」的成功率與成本/1000 次

#### 管線儀表板
- 定義三個指標：p95 延遲、成功率、成本/1000
- 用 20–50 筆小樣本跑前後版本，畫兩條線就能判斷是否有效

#### 交叉對照
- 搜索「對標產品」的文件/案例（上面提到的服務）
- 能找到就不是憑空杜撰
- 若找不到「一盒化模板」則代表機會區
