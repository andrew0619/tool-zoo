# Tool Zoo - 技術詞彙白話翻譯

## 🎯 為什麼重要

**完全正常！你只是把方向盤交給我。**

用超白話翻譯這幾個詞，讓你知道我們在幹嘛、為什麼重要。

## 📚 技術詞彙白話翻譯

### 客觀掃一遍
- **像健檢**：先看整體哪裡最可能出事（安全、成本、關鍵流程），再決定修哪個。

### 別浪費 token
- **像挑重點讀**：先取「相關檔案片段」給 AI，而不是把整個專案全餵，省錢省時間。

### 停掉自動 Actions
- **像把自動灑水器先關掉**：GitHub 自動任務容易一直跑、寄信、燒 API 費用；改成手動需要時才跑。

### RLS（Row-Level Security）
- **像每個人都有上鎖的抽屜**：資料表啟用 RLS 後，就算同一張表，彼此也只能看到自己那一列，避免外洩與越權。

### 費控（成本護欄）
- **像電費跳電器**：設定每天/每分鐘的上限、重試次數、單次最大輸出，避免 AI 帳單暴衝。

### 觀測（Observability）
- **像車上的儀表板**：記錄錯誤、延遲、花多少錢，出問題才找得到原因，也知道是不是變快了。

### e2e smoke（最小端到端冒煙測試）
- **像插電看燈會不會亮**：用最短路徑驗證「關鍵流程整條能不能走完」。
- **例**：登入→付費→權限生效；或 上傳→OCR→翻譯→PDF。

## 🤔 為什麼先做這些

### 它們是「護城河＋地基」
- 先防外洩與爆費，再確定主流程跑得通，之後加功能才不會越改越亂。

### 它們可量化
- 延遲、錯誤率、成本、是否通過冒煙，都是看得見的提升，符合你要的「效率感」。

## 👀 你怎麼知道它們在運作（只要看，不用動手）

### RLS
- Supabase 表旁的 RLS 開啟，且有 Policies
- 未登入看不到他人資料

### 費控
- 環境變數/設定裡有速率/金額上限
- 超限會被友善拒絕而不是一直扣費

### 觀測
- Sentry/PostHog 看得到事件與錯誤
- 有延遲/成本圖表

### e2e
- 有一條最小測試能一鍵跑完並得到「PASS/FAIL」

## 🎯 重點

**你不需要懂程式才能做「對的選擇」**

你負責說「什麼要被保護、什麼算成功」，我把它翻成規則和檢查點；這就是我們剛才一起做的事。

## 📊 決策依據分析

### 短答
我不是靈感亂猜，而是把你的「語言、選擇、產物」三層證據疊起來，再用約束條件與市場掃描做反推，才收斂到「三大家族（門票/救生員/值班長）」的效率套件路徑。

### 我怎麼得出來的

#### 觀察你的語言
- 你反覆講「效率、可驗證、被市場普遍接受」而不是「酷功能」或「藝術感」
- 這是系統與指標導向的語言

#### 觀察你的選擇
- 要我「客觀掃一遍、別浪費 token、先解決瓶頸」
- 停掉自動 Actions、強化 RLS/費控/觀測、要求 e2e smoke
- 這是把流程做精密、做可靠的選擇

#### 觀察你的產物
- 你會自然把混亂變結構：finance/dharma 的匯入→清理→彙總→圖表，IG 的 taxonomy/templates/catalog
- 這是「流水線」思維

#### 約束條件框定
- 時間短、單人、非程式背景、要看到真實收入與成就感
- 大平台不合適，小而可賣的「效率模組」更貼近

#### 市場掃描（簡版）
- Stripe/Supabase/觀測/結構化輸出都有「零件」，但「一盒就能上路＋SLO＋前後對照」稀少
- 這給了差異化空間

#### 類比匹配
- 門票（訂閱→權限）縮短 TTR
- 救生員（JSON 救援）把不穩定變可用
- 值班長（端到端 p95/成本/成功率）用數據說服
- 三者正好對齊你的快感來源：效率被看見且可驗證

## 🤷‍♂️ 為何你自己不容易想到

### 近距離效應
- 你在巨型專案裡看問題，直覺會往「平台」解，而不是抽成「可賣的小模組」

### 認可偏好
- 想被看見，容易瞄準大範圍題目
- 我把它折成「小但可驗收的證據」，更快拿到外部肯定

### 技術雜訊
- Webhook/RLS/觀測這些細節會讓非工程背景的人自動排斥
- 我用「門票/救生員/值班長」做低心智模型的翻譯

## 🔄 如果哪一步判斷錯了

- 我們已把依據寫進檔案與對照（你的語言、選擇、產物、約束、競品掃描）
- 你只要指出哪條不符實，我就調整模型，不會硬拗

## 🎯 總結

這些技術詞彙的翻譯和決策依據分析，幫助你理解：

1. **為什麼選擇這些技術**：因為它們是「護城河＋地基」
2. **如何驗證它們在運作**：通過可量化的指標
3. **你的角色是什麼**：系統設計師，不是程式設計師
4. **決策的依據是什麼**：基於你的語言、選擇、產物的三層證據

這樣你就能在不需要深入技術細節的情況下，做出正確的決策和判斷。
